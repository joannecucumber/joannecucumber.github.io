Forest：從買斷到訂閱

重新定義訂閱價值，同時處理 Free 升級、Premium（買斷）再轉換，以及身分權益與回訪節奏兩項基礎。

專案總覽

三項相連的產品工作，支撐一次商業模式轉型

Forest 從一次買斷走向訂閱，首先要定義「每個月持續提供什麼，才值得使用者長期付費」。同一個方案還要面對兩種起點：Free 使用者需要升級理由；Premium（買斷）使用者已經付過費，原有權益不能被收回，也需要看懂訂閱另外多了什麼。

設計工作因此分成三條相互支撐的路徑：Service Level 定義訂閱價值；Seekr ID 負責接續身分、資料與付費權益；任務系統建立每日與每月的回訪節奏，擴大後續可進入訂閱轉換的活躍使用者池。

我的角色
公司決定產品目標與商業方向，設計方向與落地做法由我主導。驗收條件與每期開發範圍主要由 PM 推進；Rive 領獎動畫由動畫師製作，我負責流程、狀態與觸發時機。

轉型挑戰

一個訂閱，面對兩種完全不同的轉換難題

Forest 的核心專注體驗已經成立，但買斷模式無法持續回應內容更新與營運投入。訂閱轉型不只是多一個付費頁，而是要重新說明產品為何值得持續付費。

USER 01

Free 使用者

尚未付費，需要先看懂升級後能多得到什麼，以及為什麼現在值得升級。

USER 02

Premium（買斷）使用者

已經擁有去廣告、進階統計與資料匯出等功能。必須保留原有權益，再證明訂閱提供的是買斷以外的新價值。

如果把兩群人放進同一條轉換旅程，Free 使用者會看不懂方案能解決什麼，Premium 使用者則可能感到原有權益被重新打包出售。

問題重構

不是設計同一個付費牆，而是建立兩條價值路徑

專案先回到 Forest 的使用循環，盤點設定目標、進行專注、完成專注、查看數據與累積長期成果等時刻。每一項功能都先確認服務誰、解決什麼需求，再討論應該放在哪個服務層級。

功能最後被放回 Guest、Free、Premium（買斷）與 Subscription 1.0 的矩陣：Guest 保留不登入也能開始專注的基本體驗；Free 透過登入取得任務、成就與好友等能力；Premium 保留買斷時已取得的進階工具；Subscription 1.0 則提供需要持續更新的內容與優惠。

設計目標

讓訂閱價值說得清楚，也讓產品基礎接得住

  1. 01
    定義持續價值

    區分既有功能與持續更新的內容，讓 Free 與 Premium 都能看懂訂閱多了什麼。

  2. 02
    保留並接續既有權益

    使用者更換帳號、裝置或恢復購買時，身分、資料與付費內容不能中斷。

  3. 03
    提高回訪，擴大活躍使用者池

    先讓更多人維持使用 Forest，再提高他們看見每月內容與進入訂閱旅程的機會。

整體策略

訂閱價值、身分基礎與回訪節奏，各自解決不同問題

01

Service Level

定義訂閱賣什麼、哪些權益必須保留，並為 Free 與 Premium 設計不同的轉換路徑。

02

Seekr ID

處理訂閱所需的身分辨識、購買紀錄與權益管理，並接續舊帳號資料。

03

任務系統

以每日與每月不同的獎勵節奏提高回訪，不把任務直接設計成催促訂閱的工具。

設計原則

01．保留既有價值，再說明訂閱新增了什麼

Subscription 1.0 以持續更新的內容為核心，而不是重新包裝 Premium 已有功能。訂閱權益包含每月專屬禮包、新內容優先購買權與會員折扣；內容涵蓋樹種、白噪音與挑戰獎勵。

內容取得方式也被整理成月度規則：專屬內容當月由訂閱使用者優先購買並享有折扣；返場後開放 Free 與 Premium 購買；挑戰獎勵保留任務條件，不能直接購買；基礎內容照常更新，不把所有新內容都鎖進訂閱。

服務層級確認後，再依 Free 與 Premium 的起點分開設計轉換旅程。Free 需要在使用相關功能時看見升級理由；Premium 不需要重新認識基本功能，而是直接比較原有權益與訂閱新增內容。恢復購買、付款失敗、網路異常、訂單綁定其他帳號與取消訂閱，也都有各自的訊息與下一步。

02．帳號遷移不能讓身分與權益斷裂

舊帳號系統無法承接訂閱所需的身分辨識、購買紀錄與權益管理。Seekr ID 因此成為訂閱的身分基礎：系統能判斷「誰已經買過什麼」，使用者換裝置或恢復購買時，也能接回原有資料與付費內容。

流程先盤點新舊帳號狀態，再把註冊、登入、第三方登入與舊帳號綁定分開處理。註冊沒有被設成購買前的硬門檻；已經有購買意願的人可以先完成交易，之後再用 Seekr ID 保存購買紀錄。

註冊誘因則放在使用者剛完成專注、正在設定專注，或準備進入商店與陽光精華的時刻。完成註冊或登入後，可取得原本需要付費的樹種與金幣：先讓使用者感受產品價值，再邀請他建立帳號。

03．先建立回訪節奏，不用任務直接催訂閱

如果使用者很少回來，能看見每月內容、進入方案比較的人也有限。任務系統負責讓更多人持續使用 Forest，擴大後續可進入訂閱轉換的活躍使用者池，不直接催促訂閱。

任務拆成每日打卡、每日任務與每月挑戰。每天需要低門檻與一點期待，因此完成後才開啟隨機禮物盒；每月挑戰需要明確終點，因此一開始就顯示最終獎勵。兩種時間尺度服務不同動機，不共用同一套獎勵邏輯。

任務卡片定義尚未開始、進行中、完成待領取、冷卻中與已領取等狀態，並補上 iPad、離線、重複領取、跨日刷新與載入失敗等情境。領獎動畫由動畫師以 Rive 製作；產品設計聚焦在領獎流程、任務狀態與動畫觸發時機。

最終設計

從理解訂閱、接續帳號，到每日與每月回訪

已上線的 Subscription 1.0 把訂閱入口分布在首頁、帳號頁、側邊欄與功能內，在使用者正接觸相關功能時說明新增價值。帳號流程負責讓購買紀錄與權益不中斷；任務頁則把每日與每月目標放進同一個可持續擴充的架構。

反思與下一步

商業模式改變時，付費頁只是最後一段

這次專案不是從新的訂閱畫面開始，而是先釐清哪些價值值得持續付費、哪些既有權益不能被動到，以及不同使用者為什麼會做出不同選擇。Service Level 定義訂閱賣什麼；Seekr ID 確保身分與付費權益正確接續；任務系統讓更多使用者持續回來。三者合在一起，才形成能運作的訂閱基礎。

Subscription 2.0（未上線）

Subscription 1.0 已在離職前上線；2.0 是後續服務層級探索，沒有進入開發，因此不列入前述成果。

這一階段將使用情境從個人延伸到共享、親子、校園與企業，並把使用歷程整理為 Recharge、Focus、Goal，再用 Basic、Retention、Superfan 區分產品投資層次。第一步只建議驗證 minimum viable expansion，以較少的新增能力測試需求。原規劃的 Kano 問卷是後續研究計畫，不寫成已完成的驗證。
